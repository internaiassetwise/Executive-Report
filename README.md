# ASW Data Insight

วิเคราะห์ CSV/XLSX ผ่าน flow เดียว: **Upload → Validate → Profile → AI → Dashboard / Report → Export**

ใช้ชื่อ โลโก้ และธีมน้ำเงิน AssetWise เดิม ไฟล์ทั่วไปและ BOQ ไม่แยกโหมด การอ่านไฟล์/คำนวณย้ายมา Python ฝั่ง backend; frontend แสดงข้อมูล JSON และไม่โหลด Pyodide เพื่อทำงานใน flow ใหม่

## เปิดใช้งาน

ต้องมี Node.js22.13+ และ Python3.10+ พร้อม SQLite

```powershell
npm install
python -m pip install -r backend/requirements.txt
npm run dev
```

เปิด http://localhost:3000 · backend http://127.0.0.1:8000 · หยุดด้วย Ctrl+C

ตั้งค่าใน `backend/.env` (มีตัวอย่าง `backend/.env.example`):

```dotenv
GEMINI_API_KEY=your-api-key
GEMINI_MODEL=gemini-3-flash-preview
```

โมเดลเริ่มต้นคือ **gemini-3-flash-preview** ใช้ thinkingระดับminimal และคำขอเดียวจากสถิติ/หลักฐานที่คำนวณแล้ว มี timeout และตรวจ JSON schema/เลขอ้างอิง/ตัวเลขที่ AI กล่าวอ้าง Keysอยู่ฝั่ง backend เท่านั้น หากยังไม่ตั้ง key หรือ provider มีปัญหา ผลคำนวณ Dashboard และรายงานยังเปิดได้ พร้อมแจ้งสถานะ AI และปุ่มลองใหม่

แก้ค่าขีดจำกัดและ `PYTHON_BIN` ได้ใน backend/.env หลังเปลี่ยนค่าให้ restart เซิร์ฟเวอร์ ถ้าเปลี่ยน origin/port ให้แก้ `FRONTEND_ORIGINS` และ frontend `BACKEND_URL` ตามตัวอย่าง

## สิ่งที่ใช้งานได้

- เลือกไฟล์ก่อนเริ่ม แสดงชื่อ/ขนาด ตรวจนามสกุล MIME เนื้อหา หัวคอลัมน์ ไฟล์เสีย และขีดจำกัด
- อ่านหลายชีต รวมชีตซ่อน แจ้งชีต/แถวว่างที่ข้าม และรักษาเลขแถวต้นฉบับ
- Background jobs พร้อมสถานะการอ่าน คำนวณสถิติ AI และสร้างรายงานจาก backend จริง
- Profiling: ชนิดข้อมูล ค่าว่าง ค่าที่ไม่ซ้ำ แถวซ้ำ min/max/mean/median/std/sum ช่วงวันที่ หมวดหมู่ outliersแบบIQR และ correlations
- KPI และกราฟเลือกจากโครงสร้างจริง: trend, category, distribution, part-to-whole, scatter ไม่สมมติชื่อ sales/revenue
- Dashboard, Report, Data และ Analysis พร้อมที่มา/หลักฐาน/วิธีคำนวณ
- Previewแบบpagination ค้นหาทั้งข้อมูลหรือเฉพาะคอลัมน์ และเรียงค่าตามชนิดข้อมูล
- รายงาน10หัวข้อ พร้อม executive summary, findings, trends, segments, risks, quality, recommendationsและmethodology
- ดาวน์โหลด **PDF แบบจัดหน้ารายงานจริง**, **Excel summary**, **CSV ของชีตที่เลือก** พร้อมป้องกัน formula injection
- วิเคราะห์ใหม่พร้อมเป้าหมายที่ต้องการเน้น ยกเลิก/ลบ dataset และเก็บ sessionชั่วคราวในแท็บเดิม

## รูปแบบข้อมูลและขีดจำกัด

CSVรองรับUTF-8/UTF-16 BOM และตัวคั่นcomma/semicolon/tab/pipe; ExcelรองรับXLSX ครั้งละหนึ่งไฟล์ หลาย worksheet

ใช้หนึ่งตารางต่อชีต แถวแรกที่มีข้อมูลต้องเป็นหัวคอลัมน์ข้อความครบและไม่ซ้ำ ไฟล์ BOQ ที่มีหัวรายงาน/merged headersหลายชั้นต้องจัดเป็นตารางก่อน ระบบไม่สลับไป engineเฉพาะBOQและไม่ลบแถวรวมเอง สูตรExcelแสดงเป็นข้อความและแจ้งเตือน ไม่คำนวณสูตร

ค่าเริ่มต้น25MiBต่อไฟล์,100,000แถวรวม,200คอลัมน์ต่อชีต,2ล้านเซลล์,50ชีต,100MBหลังคลายXLSX หากเกินจะแจ้งข้อผิดพลาด ไม่มีการตัดแถวเงียบ ๆ ตัวเลขในหน้าจออ่านจาก backend config

สถิติคำนวณจากข้อมูลที่เก็บทั้งหมด กราฟ/ข้อค้นพบและคอลัมน์ความสัมพันธ์มีจำนวนจำกัดเพื่อความเร็ว พร้อมอธิบายในวิธีคำนวณ จุดscatterและข้อความpreviewอาจย่อเพื่อแสดงผล แต่การค้นหา/เรียงใช้ข้อมูลเต็ม AIรับเฉพาะprofile/aggregations/evidenceไม่เกินขนาดที่กำหนด

## โครงสร้าง

```text
frontend/app/                 หน้าเว็บและ same-origin API adapters
frontend/components/
  data-workspace.tsx          upload / background status / retry
  dataset-results.tsx         Dashboard / Report / Data / Analysis
  dataset-chart.tsx           กราฟจากข้อมูลคำนวณ
  data-preview.tsx            ตารางแบบแบ่งหน้า
frontend/lib/                typed contracts, API client, binary proxy
backend/src/
  server.mjs                  HTTP limits และ config
  datasets.mjs                dataset/job lifecycle และ exports
  dataset-ai.mjs              Gemini structured reasoning
backend/datasets/
  worker.py                   อ่านไฟล์ SQLite และ preview
  analyzer.py                 สถิติ/หลักฐาน/กราฟ/รายงาน
  exports.py                  PDF/XLSX/CSV
backend/analysis/             engineเดิมเก็บไว้ ไม่ใช่ flow หน้าเว็บใหม่
```

APIหลักและข้อจำกัด deployment: [docs/DATA_PIPELINE.md](docs/DATA_PIPELINE.md)

## การเก็บข้อมูลและ deployment

เก็บไฟล์/SQLiteในพื้นที่ชั่วคราว ไม่มีการ logเนื้อหา dataset ไฟล์ต้นฉบับลบหลังparse ชุดข้อมูลลบเมื่อสั่งเริ่มไฟล์ใหม่/ยกเลิก หมดอายุ(default60นาที) หรือgraceful shutdown

รันbackendหนึ่งprocess; job IDสุ่มเป็นcapabilityและไม่มีendpointรวมไฟล์ทั้งหมด ระบบนี้ยังไม่มีบัญชีผู้ใช้/tenant ownership จึงควรอยู่หลังระบบควบคุมการเข้าถึงขององค์กร ก่อนเปิดpublicหลายผู้ใช้ต้องเพิ่มauthentication/quotasและdurablejob storage การcrashอาจเหลือไฟล์temp ใช้ephemeral volumeหรือนโยบายcleanupของhost

Hostต้องมีทั้งNodeและPython/openpyxl/reportlab/uharfbuzzพร้อมฟอนต์ไทย ยังไม่มีการdeployหรือเปลี่ยนRailway/Sitesในรอบนี้

## Flow รายงาน AI / BOQ (หน้าเดิม)

> หมายเหตุ: หน้าแรกปัจจุบันใช้ DataWorkspace ตามหัวข้อด้านบน ส่วนนี้อธิบาย flow รายงาน AI วางแผน + BOQ ซึ่งโค้ดยังอยู่ใน repo (`/api/plan`, `/api/report`, `frontend/lib/*-writer.ts`) แต่ไม่ได้ติดตั้งเป็นหน้าแรก คำว่า "หน้าเว็บปัจจุบัน" ด้านล่างหมายถึงหน้าเดิมนั้น

### Flow ปัจจุบัน: ทุกไฟล์ใช้เส้นทางเดียว

หน้าอัปโหลดใช้ขั้นตอนเดียวสำหรับทุกไฟล์ แต่ตรวจโครงสร้างก่อนเลือกเครื่องมืออัตโนมัติ หากพบคอลัมน์ราคากลางเทียบราคาเสนอจะใช้ BOQ engine เดิมคำนวณปริมาณ ราคาวัสดุ ค่าแรง ส่วนต่าง และผลกระทบทางการเงิน แล้วให้ Gemini เขียนบทวิเคราะห์ลงในรายงาน BOQ รูปแบบเดิม หากไม่พบโครงสร้าง BOQ จึงใช้ AI วางแผน → โปรแกรมคำนวณและตรวจหลักฐาน → AI เขียนรายงานข้อมูลทั่วไปแบบหัวข้อยืดหยุ่น ผู้ใช้ไม่ต้องเลือกโหมดหรือตอบคำถามระหว่างทาง

หลายไฟล์ที่เป็น BOQ รองรับทั้งผู้เสนอหลายรายในชีตเดียว แยกชีต หรือแยกไฟล์ และรวมผลตามกติกา BOQ เดิม ส่วนหลายไฟล์ที่ไม่ใช่ BOQ จะแยกตารางและกำกับชื่อไฟล์/ชีตด้วยลำดับไฟล์ โดยไม่ join หรือรวมยอดข้ามไฟล์อัตโนมัติ ขีดจำกัดรวม 400,000 เซลล์และ 15 MB ต่อไฟล์

ทดสอบตัวคำนวณและ renderer ของ BOQ: `npm run test:boq` และทดสอบ writer ด้วย `npm test`

### การเขียนรายงานอัตโนมัติ

การตรวจแผนใช้ `choice_ids` แบบ enum จากรายการจริง แล้ว backend แปลงกลับเป็นคู่ตาราง/การคำนวณ หลายหัวข้ออ้างหลักฐานเดียวกันได้ โดย Python คำนวณแต่ละรายการครั้งเดียว หากแผนไม่ผ่านจะให้ Gemini แก้หนึ่งครั้ง (รวมสูงสุด 2 attempts ต่อการวางแผน) ไม่ retry โควตาหรือข้อผิดพลาดการเชื่อมต่อ บันทึกเฉพาะรหัส validation ตำแหน่งหัวข้อ ลำดับ attempt และ response ID ลง log ไม่บันทึกแผนหรือข้อมูลไฟล์ดิบ เก็บ receipt ทุก attempt ใน JSON รายงานเมื่อสำเร็จ

รายงานทั่วไปใช้ flow AI วางแผนแล้วเขียน: `/api/plan` รับชื่อคอลัมน์ สถิติทั้งตาราง ช่วงเวลา จำนวนแต่ละหมวด ควอไทล์ จำนวน/ตัวอย่างค่าผิดปกติ และตัวอย่างสูงสุด 60 แถวต่อตารางจากตำแหน่งกระจาย กลุ่ม ช่วงเวลา และค่าสุดขั้ว (ไม่ใช่ตัวอย่างสุ่มทางสถิติ) และวัตถุประสงค์ จากนั้น Gemini เลือกชื่อรายงานและหัวข้อ 1–8 หัวข้อ พร้อมอ้างอิงการคำนวณที่รองรับ ระบบตรวจรายการก่อนให้ Python คำนวณข้อมูลเต็มตามแผน แล้ว `/api/report` เขียนบทวิเคราะห์แต่ละหัวข้อจากหลักฐานจริง หน้าตา A4/ฟอนต์/สี/ตารางเดิมยังอยู่ แต่หัวข้อและลำดับเปลี่ยนตามไฟล์และคำขอ ไม่มีวิธีวิเคราะห์หรือภาคผนวกเพิ่ม

ตัวอย่างข้อมูลถูกส่งให้ Google Gemini: ไม่ควรใส่ข้อมูลส่วนบุคคลหรือความลับที่ไม่อนุญาตให้ส่งออก โปรแกรมไม่ได้ให้ AI อ่านทุกแถว และตัวอย่างไม่รับประกันว่าเป็นตัวแทนของทั้งไฟล์ สถิติ/คุณภาพและการคำนวณใช้ข้อมูลเต็มที่ตรวจพบ ความสามารถยังจำกัดที่สถิติ การกระจาย ค่าผิดปกติ ความถี่ ค่าเฉลี่ยแยกกลุ่ม/เวลา และสหสัมพันธ์ ไม่มีการรันโค้ดที่ AI สร้างหรือ join ข้ามตาราง หากทำตามวัตถุประสงค์ไม่ได้ AI ต้องระบุข้อจำกัด ข้อความยังต้องให้มนุษย์ตรวจทาน

`plan` และ `dynamic_sections` ใน Report JSON เก็บแผนและหลักฐานที่ใช้ ส่วน `writer.requests` รวม receipt ของการวางแผนและการเขียน ทดสอบ end-to-end โดยใช้ Gemini จริงกับข้อมูลสมมติ: `node scripts/test-planned-report-live.mjs` (ใช้โควตาจริง) BOQ ยังใช้รูปแบบเฉพาะเดิมและ AI เขียนข้อความในรายงานนั้น

หน้าเว็บมี 3 ขั้นตอน: เลือกไฟล์และกรอกวัตถุประสงค์ → กด “เริ่มวิเคราะห์ข้อมูล” เพื่ออ่าน/คำนวณ/เขียนรายงาน → ตรวจทานและดาวน์โหลดรายงาน การเลือกไฟล์ยังไม่เรียก AI จนกว่าจะกดเริ่ม หน้าประมวลผลแสดงสถานะและยกเลิกกลับไปยังไฟล์ที่เลือกไว้ได้ เมื่อเสร็จจะเปิดรายงานอัตโนมัติ สำหรับ BOQ ระบบใช้เกณฑ์ที่อ่านจากไฟล์หรือค่าตั้งต้นของ engine จึงไม่หยุดถามผู้ใช้ก่อนสร้างรายงาน

ตั้ง `GEMINI_MODEL=gemini-2.5-flash` และ key ใน `backend/.env` การเรียก `/api/report` ส่งเฉพาะผลคำนวณ บริบท และชื่อหมวดข้อมูล ไม่ส่ง workbook หรือแถวข้อมูลดิบ รูปแบบ BOQ ใช้ renderer เดิม โดยแทนเฉพาะข้อความวิเคราะห์เชิงลึก Signature Pattern กลยุทธ์ และบทสรุป ตัวเลขและตารางยังมาจาก Python รายงานทั่วไปใช้ข้อความในบทสรุป ผลวิเคราะห์ และข้อเสนอแนะ โดยไม่แสดงวิธีคำนวณหรือภาคผนวกทางเทคนิค

ระบบแบ่งคำขอเขียนตามจำนวนช่องและขนาดข้อมูล หากข้อความไม่ผ่านการตรวจ จะขอให้ Gemini เขียนใหม่หนึ่งครั้งโดยเน้นคำอธิบายเชิงคุณภาพและคงตัวเลขไว้ในตาราง หากยังล้มเหลวหรือโควตาหมด หน้าเว็บหยุดที่สถานะผิดพลาดและให้ลองเขียนใหม่จากผลคำนวณที่เก็บไว้ ไม่เปิดรายงานสำรองแทนรายงาน AI หน้าเสร็จสมบูรณ์ระบุชื่อโมเดลและเวลา ส่วน `writer` ใน JSON เก็บบริบท ข้อความ และรหัสคำตอบ/จำนวน token จากผู้ให้บริการไว้ตรวจสอบย้อนหลัง การตรวจตัวเลขและรหัสหลักฐานไม่สามารถรับรองความถูกต้องของข้อสรุปเชิงความหมายทั้งหมด จึงยังควรตรวจทานก่อนใช้ตัดสินใจ

ตรวจการเชื่อมต่อด้วยข้อมูลสมมติ: `node scripts/test-report-live.mjs` (ใช้โควตา API จริง)

ข้อความด้านล่างเกี่ยวกับการกดเพิ่มคำตีความเป็นคำอธิบาย flow รุ่นเดิม; endpoint `/api/interpret` เก็บไว้เพื่อรองรับการใช้งานเดิม แต่หน้าเว็บปัจจุบันใช้การเขียนอัตโนมัติข้างต้น

อัปโหลดครั้งเดียวแล้วอ่านทุกชีตอัตโนมัติ รวมชีตที่ซ่อนอยู่ แสดงภาพรวมทุกตารางโดยไม่ต้องเลือกชีต คำนวณแยกแต่ละตารางและรวมข้อค้นพบในรายงานเดียวพร้อมที่มา ชีตว่างหรือไม่มีตารางเข้าเกณฑ์จะแสดงเหตุผล ผลลัพธ์แบ่งหน้าครั้งละ 12 รายการ ส่วนรายงานและ Report JSON เก็บข้อค้นพบครบทุกตาราง

ขั้นตอนตรวจแผน, apply, สร้าง public domain และตั้งค่า Gemini อยู่ใน [คู่มือ Railway](.railway/README.md) การ deploy จาก GitHub จะใช้เฉพาะโค้ดที่ commit และ push แล้ว


### Flow อัตโนมัติสำหรับไฟล์ซับซ้อน

ก่อนเขียน ระบบตัดหัวข้อที่อ้างหลักฐานชุดเดียวกันซ้ำ หากเหลือเกิน 12 หัวข้อจะรวมหลักฐานที่เกี่ยวข้องไว้ใต้ชื่อหัวข้อเดิมที่ AI เสนอจากข้อมูล โดยไม่เปลี่ยนเป็นชื่อหมวดสำเร็จรูปและไม่รวมตัวเลขข้ามตาราง หลักฐานของแต่ละหัวข้อถูกสรุปเป็นชุดขนาดจำกัดก่อนเขียน แล้วใช้บทวิเคราะห์เหล่านี้ต่อในบทสรุปผู้บริหารและข้อเสนอแนะ หน้ารายงานแสดงตัวอย่างผลคำนวณไม่เกิน 3 รายการต่อหัวข้อ ข้อมูลเต็มและรหัสหลักฐานทุกชิ้นยังอยู่ใน Report JSON รูปแบบ A4 และการจัดวางเดิมยังคงอยู่ จำนวนคำขอ AI อาจมากกว่าจำนวนหัวข้อเพราะมีการรวมหลักฐานเมื่อข้อมูลมาก

อัปโหลด → ตรวจโครงสร้าง → ถ้าเป็น BOQ ให้ engine เดิมจับคู่แกนข้อมูลและคำนวณจากทุกแถว แล้ว Gemini เขียนบทวิเคราะห์ลงรายงาน BOQ เดิม; ถ้าเป็นข้อมูลทั่วไปให้ Gemini วางแผนเป็นส่วนย่อย → Python คำนวณ → ตรวจหลักฐาน → Gemini เขียนรายงานทั่วไป ทั้งสองเส้นทางเปิดรายงานอัตโนมัติโดยไม่ถามผู้ใช้ระหว่างทาง

ระบบแบ่งบริบทตามตาราง คอลัมน์ และงานวิเคราะห์ แทนการส่ง workbook ทั้งก้อน คำขอวางแผนแต่ละส่วนต่ำกว่า 75 KB และเข้าคิวพร้อมกันสูงสุด 2 ส่วนจนจบ (ลดเหลือ 1 ส่วนเมื่อพบข้อผิดพลาด) โดยไม่ปฏิเสธงานเพราะเกิน 64 ส่วน มี timeout ต่อคำขอ ยกเลิกได้ และพักหลังล้มเหลวติดต่อกัน 3 ครั้ง ทั้งนี้ยังไม่มีเพดาน token หรือค่าใช้จ่ายรวมต่องาน ไฟล์ซับซ้อนจะใช้เวลาและโควตาเพิ่มขึ้น ทุกคอลัมน์และตัวเลือกวิเคราะห์ที่เข้าเกณฑ์มีส่วนที่รองรับ แต่ AI อาจไม่เลือกทุกการวิเคราะห์ ตัวอย่างที่ส่งต่อส่วนไม่เกิน 12 แถวจากชุดตัวอย่างหลากหลายสูงสุด 60 แถว พร้อมสถิติจากทั้งตาราง ไม่ใช่ตัวอย่างสุ่มที่ใช้อนุมานแทนประชากร รายงาน JSON เก็บผลคำนวณฉบับเต็ม ส่วนข้อมูลยาวที่ส่ง AI มีการย่อและระบุจำนวนที่ละไว้

ตารางที่หัวตารางหรือยอดรวมกำกวมจะจำกัดเป็นการตรวจคุณภาพและระบุข้อจำกัด ไม่เดาความหมาย หากบางงานล้มเหลว ระบบดำเนินส่วนอื่นต่อและแสดงว่าเป็นรายงานบางส่วน หากไม่มีหลักฐานหรือ AI เขียนไม่สำเร็จทุกส่วน จะไม่แสดงรายงานสำรอง ผลคำขอสำเร็จเก็บในหน่วยความจำหน้าเว็บสูงสุด 256 งานเพื่อใช้เมื่อลองใหม่ ไม่ใช่คิวถาวร: รีเฟรชหรือเปลี่ยนไฟล์แล้วเริ่มใหม่

ยังมีขอบเขตทรัพยากร: 15 MB ต่อไฟล์, รวม 400,000 เซลล์ และ 50,000 แถวต่อชีต ไฟล์เสียหายหรือเกินขอบเขตอาจถูกปฏิเสธตั้งแต่ขั้นอ่าน การรองรับหลายตารางและหลายชีตไม่ได้รับประกันว่าอ่านได้ทุก layout หรือว่า AI ตีความถูกทั้งหมด ควรตรวจทานรายงานก่อนใช้ตัดสินใจ บันทึก receipt การใช้ Gemini ใน Report JSON
